BUILD GUIDE

Compiling for bare-metal RPi4

Install the toolchain, produce a bootable kernel8.img, then flash it with the tool.
← Flasher Tool
1
Install the compiler

The ARM bare-metal toolchain — targets AArch64 with no OS/libc assumptions. Use this, not aarch64-linux-gnu-gcc, which assumes a Linux target.

sudo apt update sudo apt install gcc-aarch64-none-elf
2
Entry point — start.S

Sets up the stack and jumps into your C code.

.section ".text.boot" .global _start _start: ldr x0, =0x80000 mov sp, x0 bl main hang: b hang
3
Linker script — linker.ld

Places your code at 0x80000 — the RPi4 default load address.

ENTRY(_start) SECTIONS { . = 0x80000; .text : { *(.text.boot) *(.text*) } .rodata : { *(.rodata*) } .data : { *(.data*) } .bss : { *(.bss*) } }
4
Your code — main.c

Replace the body with your actual driver/application code.

void main(void) { while (1) { } }
5
Compile, link, convert

-mgeneral-regs-only matters — without it GCC may emit NEON/FP instructions, and those registers aren't safe to use until you've explicitly enabled and saved FP/SIMD state in bare-metal code.

aarch64-none-elf-gcc -ffreestanding -mgeneral-regs-only -c start.S -o start.o aarch64-none-elf-gcc -ffreestanding -mgeneral-regs-only -O2 -c main.c -o main.o aarch64-none-elf-ld -T linker.ld -o kernel8.elf start.o main.o aarch64-none-elf-objcopy -O binary kernel8.elf kernel8.img

kernel8.img is the raw binary the flasher tool needs — not the .elf. Take it straight to the flasher.

Questions about a specific build error aren't covered here — this is just the install + minimal skeleton to get a bootable image out the door.
